# 落地 · eric-agent-luodi-skill

把客户的一句话转成能检查、能交接的工作。默认 OpenClaw，可选 DeepSeek Harness（DSH）、Hermes 或客户已有 Agent。优先明确第一件任务的输入、输出和完成条件，再决定环境与工具。

## 先让用户用起来

本文件所在目录是独立 Skill 根目录；随包的[交付清单](references/installation-checklist.md)即可支持规划，不依赖仓库根目录或网页。不要让用户先读完整手册或收集一大串参数。

从已有信息判断是配置、检查还是更新。新交付只补问影响下一步的缺口：第一件任务、Windows/Mac、在目标本机还是另一台。已说过的信息直接沿用。用普通话给出当前步骤、你能继续做什么、客户需要参与什么和完成条件；计划中的动作不能报告成已执行。

FDE 关心目标是否对齐、客户定制是否保留、下一位工程师是否能接手。输出交付目标与简短清单，逐项附证据或缺口，结尾留下一个具体下一步。更新前先检查当前状态和差异，不从空白模板重写客户设置。

## 每一步都有用户能照着做的说明

执行中使用随包的[逐步图文引导](references/setup-guide.html)，无需完整仓库或联网；不能打开 HTML 时按[引导规则](references/guided-setup.md)在对话里展示当前步骤。每次只给一个当前动作：在哪台电脑、哪个窗口、点什么、预期看到什么、如何确认。示意图必须标注，不冒充用户截图。页面勾选只是用户记录，不能充当连接或安装证据。

用户更新了安装或模型配置进度，立即修订本次清单；保留“用户确认”与“工具验证”的区别。用户说“已配 Key”，就记录“用户已配置、实际调用待验证”，不要再次索取或重填。复用 DSH 时读[DSH 接续说明](references/dsh.md)。不要把所有工具都装成必选项。

远程 Mac 已开启远程登录、地址与账户已知时，优先让宿主在**控制端本机**打开可见的原生 SSH 终端，由用户在那里输入 Mac 登录密码；先检查宿主 SSH 能力和已有连接。不要默认让用户去目标 Mac 输入命令、生成密钥或安装 VNC。密码不是显示给 Agent，而是直接交给原生 SSH；具体分流和失败恢复见引导规则。

## 规划与交付

按[交付清单](references/installation-checklist.md)组织依赖 → 网络 → Codex/IDE → 日常 Agent → 行为规则 → Skills → 验收与接续。已有可用环境先复用，只选第一件任务所需工具。Windows 核对实际运行方式；Mac 核对 macOS、Apple 芯片或 Intel、终端与目录权限。

工作规则使用运行器支持的 AGENTS.md 等入口，只合并用户明确选择的键与规则，不导入 SOUL、USER、聊天、记忆或个人档案。规则文本与实际工具权限分别检查。凭据只记录引用，不读取值；客户资料和回执不进入公共 Skill。

连接、安装、加载、任务结果分别记录。缺少证据就说明目前能判断到哪里；不要用勾选、文档或另一台机器的结果推断完成。按[Windows/Mac 验收清单](references/verification-checklist.md)核对真实安装位置、可用打开入口和本人试用，区分工具观察与使用者确认。交接写清版本、证据、未完成项、恢复办法和下一条检查动作，私有记录保存到用户指定的本次工作目录。

## 接上业务方法与任务工具

用户需要从业务场景继续时，把交付计划接到相应入口：

- [FDE 指南](https://fde.aielsen.com/zh/)与[公开仓库](https://github.com/NewenergyEric/enterprise-ai-playbook)：梳理业务问题、工作步骤和验收标准，再带回本次清单。
- 落地：把目标落实为环境、Agent、工作规则、Skills 选择与验收交接计划。
- [FDE Tool](https://fde.aielsen.com/zh/toolkit/)：按任务选择工具与 Skills；此入口非公开，需访问权限。

只把用户选定且有权使用的工具纳入计划，记录来源、版本、依赖、输入输出与完成条件。没有 FDE Tool 权限时可继续使用用户已有的工具与技能。导航不触发下载、安装、授权申请或私有内容复制，也不扩大本 Skill 的执行范围。

## 当前执行范围

此 Skill 可独立整理 Windows/Mac 交付计划，并引导用户使用宿主已有、获授权的工具完成真实部署。配套 Python 运行器只支持 Windows 项目沙箱和合成包，不提供客户机器安装、远程连接、全局安装、Agent 启停或代理/TUN/防火墙/SSH 适配。两者分别判断：宿主有相应能力且用户已授权时，按检查、变更、验收流程继续，不为同一已授权动作重复确认；宿主缺少能力时明确缺口并给出本机操作引导。图文页面本身不连接电脑、不安装程序、不接收秘密。

用户明确要运行仓库内配置示例时，再读[Windows 示例工作流](references/project-example.md)。核对完整项目位置，先 check，再 configure/update 预览并按具体 plan_id 执行；保留身份检查、来源 pin、恢复机制、客户覆盖与分层验收。不因安装了 Skill 就认为运行器或日常 Agent 已安装。

完整项目提供 docs/getting-started.html 和 docs/installation-checklist.md 作可选参考，支持矩阵与证据在 docs/support-matrix.md。
