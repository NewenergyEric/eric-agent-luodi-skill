# 运行中的用户引导

打开随包的[图文步骤卡](setup-guide.html)，定位当前阶段；不要要求用户先读完整手册。页面是离线示意，不执行 SSH、安装或保存凭据。

## 每次给用户的卡片

> 当前：连接 Mac · 等待你输入密码  
> 操作位置：你正在使用的控制端电脑，「Mac SSH」终端窗口  
> 你做：在 `Password:` 后输入目标 Mac 的登录密码，按回车。输入时通常不显示字符。  
> 预期：原生 SSH 完成认证；随后由工具核对目标账户、系统和架构。  
> 完成条件：工具确实认证并核对身份后，再显示“已连接”。

宿主能打开本地 HTML 时直接展示；否则在对话中展示一张卡，附对应步骤图或文字。当前动作结束才切下一张。每次发生需要用户参与的登录、订阅导入或隐私权限时都展示对应卡，而非到交接时才给说明书。窗口未真正打开，不得声称已打开。

## 控制端优先的 SSH 分流

1. 已在目标本机：直接检查，不额外启用 SSH。另一台电脑：沿用用户已给的地址、账户、远程登录状态和授权，优先复用已认证会话。
2. 控制端有 OpenSSH 和可见终端：由宿主在控制端启动 `ssh -l 用户 主机`。示例 `ssh -l USER HOST` 仅为占位，必须换为用户确认的目标。Windows 可用原生 OpenSSH，Mac 可用终端；先确认客户端存在。
3. 首次连接先比对目标提供的主机指纹。无法独立比对时说明仅首次信任并固定记录，不把端口开放或首次保存指纹称为身份验证完成。指纹变化停止检查，不删除旧记录或关闭主机核验来绕过。
4. 用户在原生 SSH 密码提示中输入目标 Mac 登录密码，密码不经聊天、网页、命令参数、环境变量或脚本文件。工具不得读取终端密码输入、创建录入密码的网页或伪造密码框。不要把“本机输入密码”说成把密码显示给 Agent。
5. 后台工具不能交互时，优先打开控制端可见的原生终端进行交接。只有控制端没有可用交互入口、目标未开启远程登录、网络不通或缺少已授权接入能力时，才说明原因，让用户在目标设备做必要的一步。开启远程登录用系统设置图示；不默认要求目标端粘贴命令。
6. 认证成功后只读核对目标账户、OS、架构、PATH、已有工具和目录权限。建立窗口 ≠ 认证成功 ≠ 检查完成。会话失效先检查存活状态；确实需要重新认证时重新打开有明确名称的窗口，再给一张密码输入卡，不要求在聊天重复密码。

可见交互必须有真实窗口。宿主若只能返回无交互的命令结果，不能假装用户可在其中输入。等待用户时保留窗口与已认证连接；不因一次命令超时就重建连接。长下载在后台执行并检查进度，避免阻塞后续检查；Windows 帮助窗口应避免文本选择暂停任务。收尾关闭本次临时连接；仅在本次确实新增临时授权时精确撤销并验证，不删除已有 SSH 授权。

## 网络、下载与自行配置

| 当前步骤 | 给用户看什么 | 工具核对什么 |
|---|---|---|
| 网络 | 目标 Mac → Clash → 系统代理的示意；让用户在目标客户端导入订阅 | 活跃网络接口、核心监听、实际 HTTP/HTTPS/SOCKS 设置和所需端点；开关状态不能代替连通测试 |
| 安装 | 当前软件、下载量/总量（可获得时）、正在下载/校验/安装 | 官方来源、版本/架构、摘要或签名、实际路径；中断保留可恢复数据，不能执行不完整文件 |
| 模型 | 目标应用的模型配置入口，明确 Key 只输入官方客户端 | 用户确认是否完成；只取无秘密的连接状态，实际请求测试需处于用户授权范围 |
| 系统权限 | 当前功能所需的系统设置入口与完成条件 | 只申请当前任务所需权限，不默认索要屏幕录制或完全磁盘访问 |

用户中途说“已装 DSH / 已配 Key”：更新已有工具清单和证据时间，优先复用，不覆盖配置。不能读取 `.env`、凭据文件、环境变量全集、订阅 YAML 或原始日志来证明 Key 存在；仅使用明确不会返回秘密的状态接口、版本元数据和用户反馈。外发截图应只取无秘密的区域，不捕获真实 Key、订阅、二维码、Cookie 或聊天。

## 进度与交接

每项分开记录：未开始 / 正在执行 / 等待用户 / 用户确认 / 工具验证 / 暂缓。用户选择“模型稍后连接”时安装可完成，模型验证保留暂缓。用户之后自行配置时改为用户确认，不能继续沿用旧的暂缓结论，也不能直接提升为模型调用通过。

交接包括已安装的 Chrome、ChatGPT、Codex、DSH、OpenClaw 中用户实际选用的项目；逐项记录版本、位置、启动入口与验证范围。CLI 可用不等于桌面应用存在，DSH 桌面应用存在也不要求重复安装 npm CLI。留下一个可点击/双击的启动入口和下一项具体动作。
