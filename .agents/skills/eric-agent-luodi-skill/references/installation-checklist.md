# 客户交付清单

在对话中完成这张清单即可开始。先沿用已知信息，当前一步缺什么才问什么；不要求客户一次填完所有选项。

## 先对齐一件事

- [ ] 写清第一件任务：给什么输入、要什么成果、由谁验收。
- [ ] 确认目标 Windows / Mac、执行位置和客户想保留的设置。
- [ ] 默认 OpenClaw；有明确需求时选 Hermes 或已有 Agent。

## 按顺序准备

| 步骤 | 要弄清楚什么 | 完成条件 |
|---|---|---|
| 依赖环境 | 系统、架构、实际运行方式及现有版本 | 选定发行版所需依赖在正确环境中可用 |
| 网络通路 | 现有网络是否可用，是否需要 Clash 等工具 | 实际安装工具与 Agent 能访问所需服务；秘密留在客户端 |
| Codex / IDE | 帮助者用什么工具，目标端是否需要 | 正确工作目录、文件和终端能力可用 |
| 日常 Agent | 来源、版本、安装位置、模型与账号路径 | 实际版本和健康结果可核对 |
| 行为规则 | AGENTS.md 等入口、工作流程和工具权限 | 规则实际加载，变更范围与确认边界有对应控制 |
| Skills | 第一件任务需要哪些技能 | 来源、许可、版本与权限经过审阅，实际发现并调用 |
| 任务与交接 | 客户能否独立完成第一件事 | 成果符合完成条件，留下证据、恢复办法和继续入口 |

工作规则只合并明确更改的部分。SOUL、USER、个人记忆、聊天和凭据不复制进模板或 Skill。

## 用具体成果验收

例如会议纪要整理：每条行动有负责人和期限；缺失信息明确列出，不擅自补造。分别核对文件安装、实际加载和任务成果。发现不能继续的环节，记录原因和下一步；计划不能充当执行证据。

## 交接时留下

- 本次目标代号与任务，不写客户秘密。
- 使用的版本与来源、保留的定制、做了哪些变更。
- 各项证据、尚未完成的部分、恢复办法。
- 下一位接手者先检查什么、接着说哪句话。

可直接说：“检查这个客户上次做到哪里，再列出下一步。”或“更新这个 Skill，只合并我指定的变化。”

这张清单支持规划。真实客户电脑安装与连接不属于本运行器执行范围；用户要试完整仓库的 Windows 合成包时，使用[项目示例](project-example.md)。
